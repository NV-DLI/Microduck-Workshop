1.2 准备环境与获取代码#

要完成前面介绍的仿真实验，先准备一个共用的运行环境。本节构建课程容器、挂载数据与模型，并检查 Isaac Sim 与 GPU 是否可用。

操作实验 · Ubuntu 24.04 · x86_64 / arm64 · Docker

需要什么#

课程的全部实验都在一个课程容器里运行：Isaac Sim 6.2、Isaac Lab 的 Microduck 开发快照与 Newton 都装在同一个镜像里。宿主机只负责构建和启动容器、显示仿真窗口，并保存数据和结果。

运行实验需要您自备配有 NVIDIA DGX 系统 GPU 或 RTX GPU 的计算机，并满足 Isaac Sim 的显存、RTX 渲染与驱动要求。容器支持 Intel / AMD 的 x86_64 CPU 和 DGX Spark 的 ARM CPU（aarch64）。全部实验仅在 DGX Spark 上测试过；这不代表必须使用 Spark，其他硬件的性能与可运行规模需在本机确认。推荐使用 Ubuntu 24.04 桌面环境。

宿主机需要 NVIDIA 驱动、Docker 与 NVIDIA Container Toolkit、Git，以及一个能显示窗口的桌面会话。镜像中的软件版本固定如下：

组件

课程配置

容器基础

CUDA 13、Ubuntu 24.04、Python 3.12

仿真平台

Isaac Sim 6.2

训练框架

Isaac Lab 开发快照（e527032b）

物理后端

Newton 1.8.0.dev0（71eeba16）

学习

RSL-RL 5.5.1（PPO）

本课沿用 NVIDIA 官方 Microduck 教程 的 main 分支实现，固定到包含 Microduck 任务与 BAM 电机模型的 Isaac Lab 源码快照，并非 3.0.0 GA。课程单独锁定与配套策略模型匹配的 Newton 版本，而不直接跟随上游默认依赖。容器会自动安装表中的指定版本，您无需手动选择源码提交。

下载课程代码#

在宿主机的桌面终端中运行下面的命令。

Terminal · 宿主机#
cd ~
git clone https://github.com/NV-DLI/Microduck-Workshop.git
cd Microduck-Workshop

固定的课程模型（models/ 不到 60 MB）和第 3 部分用到的预训练结果与训练日志（datasets/ 约 50 MB）都随仓库下载；您自己运行得到的结果写在 outputs/，与它们分开保存。

Workspace#
Microduck-Workshop/
├── docker/        # 镜像、启动配置与容器内辅助命令
├── lab/           # 仿真与学习代码（启动时实时挂载进容器）
├── scripts/       # 实验入口（同上）
├── models/        # 固定课程模型（容器内只读）
├── datasets/      # 示例数据与预训练 PPO 结果（容器内只读）
└── outputs/       # 您的运行结果（容器内可写）

构建课程容器#

在仓库根目录运行。首次构建预计需要下载 约 10–12 GB 的文件，主要是 Isaac Sim / Kit、PyTorch 与 CUDA 依赖，还包括 CUDA 基础镜像和系统软件包。网络较慢时可能等待较长时间；CPU 架构、下载缓存和依赖包会影响实际下载量。构建后的镜像约 21 GB，构建缓存也会占用空间，建议至少预留 50 GB 空闲磁盘。

Terminal · 宿主机#
docker compose -f docker/compose.yaml build

镜像按 lab/environment/uv.lock 安装与课程完全相同的软件版本，并校验 Isaac Lab 源码包的 SHA-256。之后修改 lab/ 或 scripts/ 不需要重新构建：启动时这两个目录会直接挂载进容器。

启动容器并进入终端#

先准备一次宿主机上的输出与缓存目录，再允许容器在您的桌面上打开窗口，最后在后台启动容器。

Terminal · 宿主机#
./docker/prepare_host.sh
xhost +local:
docker compose -f docker/compose.yaml up -d
docker exec -it microduck-workshop bash

prepare_host.sh 会检查 DISPLAY 和 XAUTHORITY 是否指向您的桌面会话；如果提示为空，请在桌面里打开的终端中运行。up -d 让名为 microduck-workshop 的容器在后台持续运行；docker exec -it 在这个容器里打开一个终端，提示符会变成 (microduck)，当前目录是 /workspace/Microduck-Workshop。

之后所有实验命令都在这个容器终端里运行，页面上会标注“容器内”。用 Ctrl+C 停止某个实验，只会结束这一条命令，容器仍在运行，可以接着输入下一条。

回到同一个容器

关闭了终端，或者需要第二个终端（例如 3.3 节一边训练一边看 TensorBoard）时，在宿主机运行 docker exec -it microduck-workshop bash，就会回到同一个容器，之前的输出都还在。容器停止后（例如重启了电脑），在仓库根目录再运行一次 docker compose -f docker/compose.yaml up -d 即可；数据、输出和缓存都保存在宿主机上。全部练习结束后，用 docker compose -f docker/compose.yaml down 停止并移除容器。

命令里的相对路径（例如 models/walk.onnx）就是宿主机仓库里的同名文件。着色器和编译缓存保存在宿主机的 ~/.cache/microduck/ 下，第二次启动会快很多。

确认可以开始#

在容器内运行下面的命令。

Terminal · 容器内#
python3 scripts/run.py doctor
python3 scripts/run.py inspect-model --model models/walk.onnx

doctor 逐一核对模型文件的 SHA-256，并检查 CUDA、显示变量和各软件包版本；所有项通过后再继续。inspect-model 显示行走模型的输入输出名称、形状和 SHA-256。如果 CUDA 显示为不可用，先在宿主机运行 nvidia-smi 确认驱动正常，并确认容器已启用 GPU 访问。

第一次打开 Isaac Sim

第一次打开窗口时需要编译着色器、加载资源，可能要等几分钟；缓存保存在宿主机后，之后会快很多。窗口出现在宿主机桌面上，点击窗口后键盘操作才会生效。

检查通过后，保持容器运行，进入 2.1 节 的球场：先由您判断方向和出脚时机，让已训练的策略负责迈步与踢球。
