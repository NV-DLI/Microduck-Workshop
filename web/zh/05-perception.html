SELF-PACED WORKSHOP

用 Isaac Sim 相机感知足球

用 Isaac Sim 的 RTX 相机与深度观测复现传感器链路，再把图像检测、距离和身体姿态转换成导航可用信息。

第 5 章 · 实验 · 建议预留 40 分钟 · 检测训练可选

任务：把图像中的目标变成可用观测

行走策略知道如何控制身体，却不知道足球在哪里。Isaac Sim 可以在同一 USD 场景中让 RTX RGB、深度和机器人头部姿态按统一时钟更新，便于重复检查视角、遮挡与时间对齐。本章先用固定检测器在图像中找出足球与球门，再理解这些二维结果如何与 ToF、IMU 和头部运动学结合。目标检测回答“是什么、在图像中的哪里”；距离、方向和观测是否仍有效，则需要额外的几何与时间信息。

之所以选择学习型检测器，是因为目标大小、视角和背景都会变化。与手工设定颜色阈值相比，检测模型可以从标注样本中学习特征；代价是需要覆盖目标条件的数据和独立验证。Isaac Sim 支持在受控场景中生成图像和标注，适合系统改变相机位姿、光照和遮挡；但当前课程传感器 rig 明确不输出物体语义真值，练习集标签也不是运行时从场景自动读取。课程先提供固定模型作为基准，再用现有小数据集体验训练。

这里加载课程固定权重，以 640 的推理图像尺寸运行，并将检测框保存到新的输出目录。界面中的框会映射回原图坐标；不能将缩放后图像中的像素坐标直接用于原始相机内参。

在代码中，Isaac Lab 的 Camera 配置把相机放到场景中的指定位置，并选择 Isaac Sim 的 RTX 渲染器输出 RGB 图像。下面的内参矩阵用于相机投影，渲染尺寸按标定参数在图像边缘预留了额外范围（过扫描）。渲染完成后，再经过标定重映射得到检测器使用的图像；代码中的 render_width/height 表示重映射前的尺寸。相机的安装姿态、内参和输出类型因此可以与机器人模型一起检查。

三个互补的信息来源

来源提供的信息局限
RGB目标在图像中的位置不直接给出绝对距离
ToF前方 64 个分区的距离无效分区不能当作空地
身体 IMU身体姿态与角速度不是球或球门定位器

Isaac Sim 在同一 USD 场景中生成与机器人头部姿态同步的 RTX RGB 和深度图，课程再把深度按 VL53L8CX 的 8 × 8 视区采样。RGB 检测器判断哪些区域可能是球，ToF 提供前方分区距离，机身 IMU 帮助在正确坐标系中解释射线。这样可重复改变视角、距离和姿态并保留时间戳；但 ToF 不是环视激光雷达，任何一种传感器也不能独立给出完整世界状态。

本课程的 Beta 仿真配置采用 GC2093 相机和 VL53L8CX ToF，图像处理分辨率为 960 × 540，频率为 15 Hz。镜头视场、畸变、噪声和安装位姿都是明确的仿真假设，迁移到真实设备时必须重新标定。当前传感器 rig 只提供 RGB、深度、IMU 和时间信息，没有把 Isaac Sim 的物体语义真值交给控制器，也不会自动生成本章练习集的 YOLO 标签。

数据集、标签与检测指标

练习集包含 40 张图像，按 24 / 8 / 8 划分为训练集、验证集和测试集。训练集用于更新参数，验证集用于观察训练过程与选择模型，测试集应留到方案确定后再使用。无论标签来自人工标注还是另行搭建的 Isaac Sim 合成数据管线，都应把图像、标签、场景参数和划分规则一起保存，防止相邻近似帧跨集合泄漏。当前小样本集仅用于跑通训练流程，不能代表真实部署中的全部光照、遮挡、距离和背景条件。

YOLO 边界框标签归一化
\[x_c=\frac{x_{\min}+x_{\max}}{2W},\quad y_c=\frac{y_{\min}+y_{\max}}{2H},\quad w=\frac{x_{\max}-x_{\min}}{W},\quad h=\frac{y_{\max}-y_{\min}}{H}\]

每行标签按 class x_center y_center width height 排列；类别 0 为足球，类别 1 为球门，四个坐标量均按图像尺寸归一化。训练前，应将标签绘制回原图，检查边界框是否贴合目标；这比只确认文本文件存在更有意义。

检测质量的三个基本量
\[\mathrm{IoU}=\frac{|B_p\cap B_g|}{|B_p\cup B_g|},\qquad P=\frac{TP}{TP+FP},\qquad R=\frac{TP}{TP+FN}\]

IoU 衡量预测框与标注框的重合程度；精确率 P 表示检出目标中有多少是正确的，召回率 R 表示真实目标中有多少被检出。mAP 综合各类别的精确率—召回率表现；mAP50 使用 IoU = 0.5，mAP50–95 则对多个 IoU 阈值取平均。这些指标都不同于射门成功率。

在一次相同配置的运行记录中，results.csv 第 5 轮的累计时间约为 6.05 秒，验证 mAP50 约为 0.00132，完整程序的启动耗时另计。这表明短练习工作流能够跑通，但模型效果很差；后续任务仍使用课程固定检测器。还应查看保存的标注图、漏检和误检，不能只关注损失是否下降。

扩充数据时，可利用 Isaac Sim 对相机位姿、光照、材质与遮挡做受控变化，并保存与每张图像对应的场景参数和标签来源；仍应按场景或序列划分数据，避免相邻近似帧同时进入训练集和测试集。合成覆盖不能替代真实相机测试，尤其是镜头畸变、噪声和材质反射差异。训练时间取决于数据量与预算；可先用短练习测量每轮耗时，再安排后续实验。

后续仍使用课程检测器

第六章和第七章默认加载 models/detector.pt，短训练产生的模型不会替换该文件。检测 mAP 衡量的是检测质量，不能等同于机器人的射门成功率。

从像素射线理解距离估计

单个像素只能确定一条观测方向，不能直接给出距离。先用内参矩阵 K 将像素坐标反投影到相机坐标系，再用相机外参把射线转换到所需坐标系。下面以“射线与地面相交”为例，说明几何约束如何提供尺度；实际足球中心高于地面，必须使用与球体和相机相符的几何模型，不能把边界框中心直接视为地面接触点。

针孔相机的反投影
\[\widetilde{\mathbf d}_C=K^{-1}[u,v,1]^{\mathsf T},\qquad \mathbf d_B=R_{BC}\frac{\widetilde{\mathbf d}_C}{\|\widetilde{\mathbf d}_C\|},\qquad \mathbf p_B=\mathbf o_B+\lambda\mathbf d_B\]
已知平面时的射线交点
\[\mathbf n^{\mathsf T}\mathbf p+d_0=0\quad\Rightarrow\quad\lambda=-\frac{\mathbf n^{\mathsf T}\mathbf o+d_0}{\mathbf n^{\mathsf T}\mathbf d}\]

分母接近 0 时，射线与平面几乎平行；λ ≤ 0 时，交点不在射线前方。遇到这些情况应拒绝该结果，而不是强行给出距离。相机姿态还必须与图像采集时刻对齐；头部转动后若用新姿态解释旧图像，会引入偏差。

Python · 几何原理示意，不是独立运行脚本
ray_camera = inv_K @ np.array([u, v, 1.0])
ray_camera /= np.linalg.norm(ray_camera)
ray_body = R_body_camera @ ray_camera
denominator = normal @ ray_body
# 使用交点前，检查分母是否接近零以及距离的符号。
distance = -(normal @ origin + plane_offset) / denominator
point_body = origin + distance * ray_body

这段示意代码用于对应公式；完整任务还会使用 Isaac Sim RTX 图像、32 × 32 深度产品采样得到的 8 × 8 ToF 近似、头部运动学和有效性检查。传感器挂载到实际 Newton 头部连杆姿态，而不是保持世界水平的虚拟云台。验证时，应同时检查检测框、相机内参、估计位置和时间戳；检测框正确并不意味着三维位置一定正确。

从一个像素到一条空间射线

在光学相机坐标系中，像素 \( (u,v) \) 对应的射线方向与 \( [(u-c_x)/f_x,\,(v-c_y)/f_y,\,1]^{\mathsf T} \) 成比例。内参中的 \(f_x,f_y\) 是以像素为单位的焦距，\(c_x,c_y\) 是主点。射线只表示方向；确定距离还需要已知几何或其他传感器提供约束。

相机坐标系通常规定 x 轴向右、y 轴向下、z 轴向前；本课程的机身坐标系则规定 x 轴向前、y 轴向左、z 轴向上。两者之间必须依据相机相对于机身的旋转和平移进行变换，不能直接把同名坐标轴上的数值相加。头部转动也会改变这一变换，因此目标定位必须使用对应时刻的头部关节状态。

ToF 的 8 × 8 距离网格并不是 64 个独立的物体标签。单个网格可能同时覆盖地面和球，近距离反射也可能产生无效读数。应先检查测距状态和有效范围，再判断这些数据能否支持图像中的目标。若把“没有有效测量”误解为“前方没有障碍”，后续导航就会建立在错误前提上。

曾经看见，不等于现在仍然知道

机器人移动或低头后，球可能暂时离开画面。虽然可以利用里程计在短时间内更新球的相对位置，但这种记忆会不断累积误差。一旦观测过期、ToF 数据无效或地面约束丢失，就应停止移动并重新观察，不能把缺失数据当作空地。

检查理解

检测器画出了准确的球框，就可以直接把球框中心当作世界坐标吗？

查看解析

不能。像素位置只能表示图像中的方向，还需要相机模型、相机姿态以及距离或几何约束，才能估计目标的空间位置。

检查标签与检测结果

练习集共包含 40 张图像，按照 24 / 8 / 8 划分为训练集、验证集和测试集。类别编号 0 表示球，1 表示球门。YOLO 标签的每一行采用 class cx cy width height 格式，后四项均按图像宽高归一化。例如，中心横坐标 0.5 表示画面宽度的一半，而不是世界坐标中的 0.5 米。Isaac Sim 支持为受控场景构建合成数据与标注流程，这有助于系统覆盖视角、光照和遮挡；本课程当前小数据集仍应按其现有标签检查，不能把场景中的物理真值或语义 ID 当作检测器已经见过的答案。

请从推理输出中各选一张检测正确的图像和一张困难样本，分别检查漏检、误检与检测框偏移，并观察同一物体在大小和位置上的变化。再高的置信度也无法修复相机标定错误，更不能让二维检测框自动获得深度信息。进入导航阶段前，还必须检查距离、姿态、时间戳和数据有效性。

检查理解

标签中的球框中心为 (0.6, 0.4)，是否可以直接作为导航目标 (0.6 m, 0.4 m)？

查看解析

不能。这是归一化图像坐标。需要相机模型和距离或地面约束，才能得到机器人坐标中的位置。
