Microduck Workshop / 课程章节

SELF-PACED WORKSHOP

让机器人看见足球

将图像检测、距离观测和身体姿态结合，得到导航可使用的信息。

第 5 章 · 实验约 40 分钟 · 检测训练可选

三个互补的信息来源

来源提供的信息局限
RGB目标在图像中的位置不直接给出绝对距离
ToF前方 64 分区距离无效分区不能当作空地
身体 IMU身体姿态与角速度不是球或球门定位器

RGB 检测器回答“图像里哪里像球”。ToF 提供前方 8 × 8 分区的距离；它不是环绕机器人一圈的激光雷达。身体 IMU 帮助估计姿态，让距离和图像射线有合适的坐标解释。任何一个传感器都不能单独提供完整世界状态。

本课程仿真使用 GC2093 相机配置和 VL53L8CX ToF 配置；图像处理为 960 × 540、15 Hz。镜头视场与噪声参数属于仿真假设，真实设备需重新标定。

先运行固定检测器

Terminal · Bash
python3 scripts/workshop.py detect \
  --model models/detector.pt \
  --source datasets/sample/images \
  --output outputs/detection-01

预期结果：生成带有球与球门检测框的图片。逐张检查球较小、接近画面边缘或被遮挡时的表现。检测置信度是模型的输出分数，不是“这个目标一定正确”的保证。

练习训练一个检测器

Terminal · Bash
python3 scripts/workshop.py train-detector \
  --data datasets/sample/data.yaml \
  --epochs 5 \
  --batch 8 \
  --seed 303 \
  --output outputs/student-detector-01

小样本和 5 个 epoch 用来体验数据、标签、训练和验证流程，不是完整训练配方。打开输出中的损失曲线与验证图片，检查标签是否覆盖了球和球门。正式提高效果时，应增加场景多样性，并保持训练、验证、测试场景分离。

后续仍使用课程检测器

第六、七章默认加载 models/detector.pt。短训练得到的模型不会替换它。检测 mAP 衡量检测质量，不等于机器人射门成功率。

从一个像素到一条空间射线

设检测框中心为像素 (u, v)，相机内参包含焦距 (fx, fy) 与主点 (cx, cy)。在常用的相机坐标约定中，射线方向与 ((u−cx)/fx, (v−cy)/fy, 1) 成比例。这个公式只告诉你目标朝哪个方向，无法区分近处的小球和远处的大球；还需要距离或已知几何约束。

相机坐标常用 x 向右、y 向下、z 向前；身体坐标在本课程中用 x 向前、y 向左、z 向上。必须先使用相机相对身体的旋转和平移进行变换，不能直接把两种坐标中的同名轴相加。头部转动也会改变这个变换，所以目标定位需要对应时间的头部关节状态。

ToF 的 8 × 8 距离格不是 64 个独立的物体标签。一个格可能同时覆盖地面和球，近处反射也可能无效。应先检查距离状态与有效范围，再考虑它是否支持图像中的目标。将“没有有效测量”解释为“前方没有障碍”，会让后续导航建立在错误前提上。

看见过，不等于现在仍知道

机器人移动或低头后，球可能暂时离开画面。可以用里程计短暂更新球的相对位置，但记忆会积累误差。观测过期、ToF 无效或地面约束丢失时，应停止并重新观察，不能把缺失数据当作空地。

检查理解

检测器画出了准确的球框，就可以直接把球框中心当作世界坐标吗？

查看解析

不能。像素位置给出的是图像方向。还需要相机模型、相机姿态和距离或几何约束，才能估计空间位置。

检查标签与检测结果

练习集有 40 张图像，按 24 / 8 / 8 分为训练、验证、测试。类别编号 0 表示球，1 表示球门。YOLO 标签每行写为 class cx cy width height；后四项用图像宽高归一化。例如中心横坐标 0.5 表示画面宽度的一半，不是世界坐标中的 0.5 米。

从推理输出中选一张正确图和一张困难图，分别检查是否漏检、多检、框偏移。再看同一物体的大小与位置变化。较高置信度不能修复镜头标定错误，也不能让二维框自动获得深度。进入导航之前，还需要距离、姿态、时间戳和有效性检查。

检查理解

标签中的球框中心为 (0.6, 0.4)，是否可以直接作为导航目标 (0.6 m, 0.4 m)？

查看解析

不能。这是归一化图像坐标。需要相机模型和距离或地面约束，才能得到机器人坐标中的位置。
