4.2 设计射门阶段#

4.1 节把传感器读数变成了球和球门的位置。本节用这些位置设计接近、对准、出脚与恢复的控制过程，并阅读各阶段实际使用的反馈控制与切换代码。

第 4.2 节 · 预计学习时长 35 分钟

为什么采用板载策略#

Microduck 使用基于 Rockchip RK3566 的主控板，其中的小型神经网络加速器（NPU）为单核 INT8，算力 0.8 TOPS；运动策略以 50 Hz 循环运行（官方 README ↗，NPU 说明 ↗）。这样的算力难以承担 GR00T 这类约 30 亿参数的视觉-语言-动作模型（VLA）的低延迟推理。因此板载策略选择小型检测器，配合几何计算、直线接近和已训练的行走与踢球技能。

从传感器到动作：沿直线接近足球#

Isaac Lab（基于 Isaac Sim，物理引擎为 Newton）仿真机器人、传感器和球场，并运行学到的策略。这里使用没有障碍物的球场：根据 RGB、ToF 和关节数据估计球的位置，在球后选一个朝向球门的准备站位，再把当前位置与站位连成直线。机器人沿这个方向接近，行走过程中持续用观测和位置记忆修正速度，接近足球时减速并调整。

组成部分

做什么

YOLO26n 检测器

在 RGB 图像中用识别框标出球和球门

几何计算

由识别框、ToF 地面和关节角算出球与球门的位置

直线接近

连接当前位置与球后准备站位，检查直线路段是否可通行

反馈控制与阶段

根据球的位置和身体朝向更新行走速度；按条件切换阶段

行走策略

把速度请求变成 14 个关节目标，50 Hz

踢球与恢复

出脚击球，再回到站立

直线提供接近的参考方向，反馈控制负责在行走中修正偏差。高层输出前进、侧移和转向的速度请求，平衡和迈步交给行走策略完成。

射门的六个阶段#

设计阶段时，可以从成功条件倒推。踢球技能只在很小的范围内有效：球要在右脚前方，身体要朝向球门，机器人要先站稳。为了满足这些前提，需要先走到球后方的站位，再精确调整位置和朝向；而这一切的前提，是先知道球和球门在哪里。

再考虑传感器的不确定性。行走时相机晃动，所以用最近一次可靠的球位置，加上关节编码器和 IMU 估计的身体运动，持续更新球相对机器人的位置。估计可靠、位置和朝向合适时，可以连续走近；需要重新确认时才停步观察。踢球必须从静止站姿开始，所以单独设一个交接阶段。

下面按顺序介绍每个阶段，并附上实际运行的核心代码。定位与路径使用球场地图坐标；球的近距位置使用以机器人为参考、与地面水平的坐标，x 向前、y 向左。代码会在需要时转换坐标。

寻找目标#

机器人原地转头扫视，用 4.1 节的方法找到两根门柱的底点，由门柱位置算出自己相对球门的位置和朝向，再把看到的足球放到同一张地图上。单次估计可能有误差，所以要连续几次结果一致才接受。之后如果太久没看到球门，或者球的信息过旧，就回到这里重新观察。

直线接近#

目的是从远处走到球后方的准备站位。站位沿“球到球门”的方向退到球后，再向一侧偏出，让最后球落在右脚前。把估计的当前位置与这个站位连起来，就得到空球场中的直线接近方向。

代码先沿直线取点，再结合已知球场边界和当前 ToF 检查可通行范围。检查通过后开始行走。随着身体移动，球相对机器人的位置也在变化；控制器不断更新前进、侧移和转向请求，尽量保持合适的接近方向。

1确定起点与终点

从传感器估计的状态中取当前位置和球后准备站位，计算二者的直线距离。

1
snap=snapshot(case,provenance)
a,b=snap['pose'][:2],snap['goal']
distance=math.dist(a,b)

2沿直线取点

将这段直线分成不超过 2 cm 的小段，用于检查整条接近路段。

2
n=max(1,math.ceil(distance/.02))
points=[[a[0]+(b[0]-a[0])*k/n,a[1]+(b[1]-a[1])*k/n] for k in range(n+1)]

3检查可通行范围

结合球场边界和当前 ToF 检查这些点及机器人所需的空间；通过后才允许接近。

gate=check_path(points,snap)

这条直线是行走的参考，不是一开始算好距离后就不再观察。传感器持续采集，位置记忆持续更新；接近足球时，如果位置和朝向满足条件，就连续转入近距细调。通行检查不通过或信息过旧时，先停步重新观察。

接近时的转向采用 PD 形式的航向反馈。比例项（P）根据朝向误差纠偏；阻尼项（D）根据 IMU 测得的转动速度抑制继续摆动。例如，身体仍偏向右侧时，P 项要求向左转；如果已经向左转得较快，D 项就减小转向请求，减小越过目标后再转回的倾向。这里用实测角速度提供阻尼，不直接对相机角度做差分。

远处接近和近距细调复用下面的控制律。朝向误差和角速度先分别平滑，再产生限幅的转向速度请求。它交给已训练的行走策略执行，不直接给关节施加力矩。

Python · PD 航向反馈完整代码 ↗

1读取竖直方向的转动速度

用重力确定竖直方向，将 IMU 角速度投影到这个方向，得到身体实际的左右转动速度。

1
gravity = np.asarray(packet["gravity_body"], float)
up = -gravity / np.linalg.norm(gravity)
rate = float(np.dot(np.asarray(packet["gyro_body_rad_s"], float), up))

2平滑阻尼反馈

用 0.1 秒时间常数平滑角速度，减小迈步晃动对阻尼项的影响；朝向误差在前面的计算中也已单独平滑。

2
self.macro_yaw_rate += (1.0 - math.exp(-dt / 0.1)) * (
    rate - self.macro_yaw_rate
)

3P 纠偏，D 抑制摆动

朝向误差乘 2.5，再减去角速度乘 0.25，最后将转向速度请求限制在正负 0.5 rad/s。系数是控制器参数，需要结合机器人和任务调试。

3
wz = max(
    -0.5, min(0.5, 2.5 * self.track_heading_lp - 0.25 * self.macro_yaw_rate)
)

横向调整采用比例反馈：偏离射门线越远，侧移请求越大，并叠加朝向补偿。前进方向则按距离降低速度请求，近处再用预测制动停下。因此，这里的完整方案是“航向 PD、横向比例反馈、前进速度调度与制动”，三个方向各自承担不同的控制任务。

近距细调#

进入近距区域后，继续用同一套航向 PD 与横向反馈对准右脚前的目标位置。小偏差在行走中连续修正；偏差超出可调整范围时，才停稳重新观察，或在后方可通行时后退转向，为下一次接近留出空间。

除了方向要对，接近速度也要及时降下来。预测制动用同一球位锚点下最近一小段位置记录估计接近速度：接近得越快，越早触发减速。下面的代码在历史样本足够且连续时运行。

Python · 预测制动完整代码 ↗

1从位置变化估计接近速度

对最近一段时间与球的前向位置做直线拟合，得到位置变化率；前向距离减小时，负斜率对应正的接近速度。

1
mean_t = sum(a for a, _ in self.samples)/len(self.samples)
mean_x = sum(b for _, b in self.samples)/len(self.samples)
slope = sum((a-mean_t)*(b-mean_x) for a,b in self.samples)/sum((a-mean_t)**2 for a,_ in self.samples)

2按速度提前制动

将接近速度估计限制在 0–0.5 m/s，以目标距离加上与速度相关的余量计算制动触发距离，并限制在 12.5–17 cm。这里的 0.28 是经验停止时间参数，不是已标定的物理制动模型。

2
speed = max(0., min(.5, -slope))
threshold = max(.125, min(.17, .11+.28*speed))

触发制动后，速度请求在 0.16 秒内逐渐降为零。若观测或朝向需要重新确认，机器人停稳并连续静止 0.5 秒后再使用新图像；这些切换条件负责决定何时允许运动，PD 与比例反馈负责运动期间怎样纠偏。

对准出脚位置#

近距细调的目标，是让球进入右脚前方的出脚位置，同时让身体朝向球门。球还看得见时，用停稳后的观测检查位置。若球已经很近，低头仍看不到完整的球，就检查之前的可靠球位及其后连续更新的位置记忆：估计已到位、方向合适、身体与地面检查通过时，直接进入踢球交接，不再反复低头寻找。

下面是这一近距到位判断的位置范围；它还需要同时通过观测时效、连续运动估计和身体状态检查。仅仅“看不到球”不会触发出脚。

1位置估计必须有效

需要三维有限数值；缺失的观测不能当成零距离。

1
def finite(x):return isinstance(x,(int,float)) and not isinstance(x,bool) and math.isfinite(x)
def vec(v,n):return isinstance(v,(list,tuple)) and len(v)==n and all(finite(x) for x in v)

2判断是否已到脚前

连续更新的球位估计在机身前方 7–15 cm、横向右侧 10 cm 到左侧 1 cm 之间，才满足这一到位条件；还需通过朝向等检查，再停稳交接。

交接给踢球#

行走停止，头部回到踢球姿态。等身体连续静止 0.5 秒后，再确认球的位置估计、球门方向和身体状态仍满足对应的到位条件，才把控制交给踢球技能。条件不满足时先停步，重新观察和对准；后退恢复也要先检查后方是否可通行。

2判断是否完全静止

头部已经回正，机身角速度、关节速度和倾斜都足够小，才算静止。

    and np.linalg.norm(gyro) <= 0.1

踢球与恢复#

踢球技能运行一次：官方右脚踢球策略出脚，随后平滑切换到站立，并继续观察球是否停稳。这里的站立动作来自官方行走策略在零速度指令下的输出，不加载额外的踢球修正网络。板载策略不判断是否进球，由单独的评测程序用仿真真值判断。

2从踢球平滑过渡到站立

    weight = np.float32(1) - u * u * (np.float32(3) - np.float32(2) * u)

阶段主要根据观测和身体状态切换：条件不满足，就停下、重新观察或退回前一阶段，所以细调常会重复几次。局部动作有时间上限，整轮实验则由您按 R 重置。

哪些经过训练，哪些没有#

  • 检测器。 目标是在 960 × 540 的头部相机图像中找出两类物体：足球和球门。课程从一个 YOLO26n 检测器出发，用 Isaac Sim 渲染的球场图像继续训练，画面覆盖几种地面（包括课程的绿色球场）、不同的机位和球的位置。识别框标注由已知的场景几何投影到相机画面自动生成，并用渲染深度剔除被遮挡的部分。512 张用于训练，128 张用于挑选检查点，另外 128 张留作测试。

  • 行走。 官方行走策略由 Pollen Robotics 用强化学习训练，也就是第 3 部分介绍的方法；课程直接使用，权重不变。

  • 踢球与恢复。 官方右脚踢球策略同样是强化学习训练的局部技能，权重不变；这里实现了它与站立之间切换的时序逻辑。

  • 没有训练的部分。 几何计算、直线生成、速度反馈、减速和阶段逻辑都是编写出来的。
