# 5.4 从球场走向更多环境

:::{lesson-intro}
:meta: 第 5.4 节 · 预计学习时长 35 分钟

在绿色球场上把任务做稳之后，怎样通过环境域随机化和 Cosmos 3 数据扩展，让模型面对真实家庭里不同的地面、光照和布局；哪些变化可以沿用原动作标签，哪些必须重新仿真。
:::

{#first}
## 先把一个场景做可靠

本课的射门练习（2.1 节的键盘踢球、第 4 部分的板载策略和第 5 部分的 GR00T 步行射门）都使用同一个绿色足球场：同样的场地、球门、足球和光照。这是有意的安排。只有在一个固定场景中把任务做稳，失败才容易解释；如果原场景都不能稳定完成，再加十种房间，只会让问题更难定位。

但真实机器人不会只待在一个绿色球场上。家里的地面可能是木地板、瓷砖或地毯；白天和夜晚的光线不同；背景里有沙发、桌腿和杂物。5.3 节的检查点在五个验证回合中还没有进球，所以眼下的下一步是先分析固定球场上的失败、改进数据与控制，再重新评测。本节提前讨论一个后续问题：射门做稳之后，怎样逐步扩展环境。这里只讲思路和原则，不做动手练习。

{#why-variation}
## 为什么真机需要环境变化

一个只在绿色球场上训练过的模型，可能学到了一些我们并不希望它依赖的线索。比如“绿色背景里的白点就是球”，或者“球门总在画面的这个亮度范围内”。在仿真里这些线索一直成立，模型没有理由不用它们；换到浅色木地板上，这些线索消失了，模型就可能找不到球。

仿真与现实之间还有别的差距：真实相机有曝光变化、运动模糊和噪声；真实灯光会产生阴影和反光；真实地面的摩擦与仿真设置不同。这些差距统称为“仿真到现实的差距”（sim-to-real gap）。让模型在训练中见过足够多样的条件，是缩小这个差距的主要办法之一。

{#domain-randomization}
## 环境域随机化

3.2 和 3.3 节已经用域随机化（Domain Randomization）改变了舵机特性、摩擦和地形：不追求仿真与某一个真实环境一模一样，而是让选定条件在一定范围内随机变化，希望真实环境也落在范围里。看图像的 GR00T 还需要视觉条件的变化，例如光照、材质和背景。范围应依据真实使用条件选择，并在未见过的组合与边界条件下评测。

| 类别 | 可以变化的条件 | 对射门任务的影响 |
|---|---|---|
| 外观 | 地面材质与图案、墙面与背景、无关的家具与杂物 | 改变画面，动作本身不必改变 |
| 光照 | 亮度、色温、光源方向、阴影 | 改变画面，动作本身不必改变 |
| 相机 | 曝光、轻微的安装角度偏差、噪声 | 改变画面；安装角度变化较大时，看到的几何关系也会变 |
| 起点 | 机器人与球的位置、朝向和距离 | 同时改变画面和需要的动作 |
| 物理 | 地面摩擦、球的质量与弹性、关节特性 | 改变运动结果，原来的动作可能不再适用 |

一条实用的经验是：**想想你预计真实场景里会变化什么，就随机化什么**。范围太窄，覆盖不到真实情况；范围太宽，模型要学的东西太多，可能在每种情况下都变得保守。

随机化也要保持任务本身不变。球门的大小、球的大小、机器人的身体结构，以及“踢进球门算成功”的判据，都不应随着外观一起漂移。改变外观是为了让模型学会忽略无关的变化，而不是把任务变成另一个任务。

{#initial-state-variation}
## 先随机起点，再扩展房间

起点变化通常是第一步：先在同一个绿色球场内改变机器人与球的位置，检验模型能否从没见过的组合完成任务；再扩大朝向和距离的范围；最后才引入室内背景、光照与地面外观。

起点和物理条件变化后，机器人需要的动作也变了，必须重新运行物理仿真，让老师在新条件下重新给出动作；原来轨迹上的动作标签已经不再适用。只有纯外观变化（同样的位置、同样的运动，只是画面看起来不同）才可能沿用原来的动作标签。

{#diagnose}
## 先分清是“看不清”还是“做不到”

扩展到新环境后，模型失败的原因各不相同，需要的帮助也不同：

| 看到的失败 | 更可能需要的帮助 | 接下来要验证 |
|---|---|---|
| 换光照后找不到球 | 视觉数据覆盖与外观随机化 | 在未参与训练的光照下，找球与完整射门是否都恢复 |
| 看见球，却从侧面越走越偏 | 偏差状态的纠正示范 | 纠正数据是否覆盖了模型实际走到的偏差状态 |
| 在新地面上踢球后站不稳或摔倒 | 物理参数随机化与底层技能的适应 | 实测的摩擦与接触是否落在仿真范围内 |
| 家具挡路，原路线不可用 | 布局变化与可执行的绕行技能 | 新布局下是否有可执行路线，绕行后仍能完成射门 |

外观随机化改变“看到的样子”，物理随机化改变“真实的运动”，两者要分别设计、分别检验。

{#direct-joints}
## 另一种选择：让 GR00T 直接输出 14 个舵机动作

本课的 GR00T 输出 8 维高层请求，由底层行走策略把请求变成 14 个舵机的目标（5.2 节）。也可以设想去掉中间这一层，让 GR00T 直接输出关节目标：

```{learning-flow}
label: 设想：GR00T 直接输出 14 个关节目标
nodes:
- [观察与指令, RGB 图像、任务指令与身体状态]
- [GR00T, 预测一段动作]
- [关节目标序列, 按时间排列，每一步 14 个目标角度]
- [关节控制器, 舵机位置控制、限幅与安全保护]
details:
- 输入类型仍是相机图像、任务指令和身体状态；状态编码与动作标签需要按 14 关节接口重新设计。
- 模型一次预测接下来一小段时间的动作。
- 每一步直接给出 14 个舵机的目标角度，不再经过行走策略。
- 舵机仍要做位置控制，目标还要经过限幅和变化速率限制；推理超时或输出异常时，机器人应进入受控停止。
layout: learning
loop: true
caption: 这只是一种设计设想，本课没有训练或验证这种控制方式。
```

它的潜在好处是更灵活：动作不再受底层技能限制，同一个模型也可能学会更多种任务。代价是要求高得多：

- **数据**：需要更多、更多样的示范，连失衡后的恢复也要从示范中学到，因为不再有底层策略负责平衡。
- **延迟与平衡**：动作块可以逐步执行，但模型仍需及时根据新观测纠偏。要处理动作的连续执行、过期动作和失衡恢复；远端推理还要计入网络延迟。

{#cosmos}
## Cosmos 3：为同一段动作补充视觉变化

在仿真中改变材质和灯光，需要为每种条件准备资产并重新渲染。另一条补充途径是用生成模型直接改变已有视频的外观。

NVIDIA Cosmos 是面向物理 AI 的世界基础模型平台。Cosmos 3 把理解场景（推理）、生成视频（世界生成）和生成动作放进同一个模型家族。对本任务，一个适合研究的用法是视频迁移（video transfer）：以一段已有的仿真示范视频为基础，用边缘、深度或分割等结构条件约束画面中物体的位置和形状，再用文字提示改变光照、地面或房间外观，生成新的候选视频。

```{learning-flow}
label: 改变视觉外观，检查动作标签是否仍然成立
nodes:
- [可靠原始轨迹, 图像、状态与执行动作]
- [Cosmos 3 迁移, 生成受条件约束的外观]
- [检查数据一致性, 目标几何、接触与时间]
- [训练与对照评测, 陌生环境中的自主成功]
details:
- 源数据首先要有正确的动作和时间对应关系。原示范没有教会的行为，改变它的外观也补不出来。
- 结构条件帮助保持布局，提示词改变光照或房间外观。生成结果只是候选数据，即使有条件约束，也可能出现错误的帧。
- 检查球和球门的大小与位置、机器人的形状、接触时刻和跨帧连续性。如果球被生成到脚的另一侧，原来的动作标签就不再成立，这段数据应当丢弃。
- 在相同示范量与训练预算下，与不加生成数据的模型比较；把新房间或新组合留给测试，才能判断扩展是否有帮助。
layout: learning
loop: false
```

用生成视频扩充数据时，有几条约束必须守住：

- **几何必须保持。** 球、球门、相机视角和机器人的相对位置不能变。动作标签是“在这个几何关系下该怎么做”，几何一变，标签就失效。
- **动作标签的语义必须保持。** 生成只改变图像，状态和 8 维请求原样沿用；这只有在外观变化不影响“该怎么做”时才成立。
- **时间上要一致。** 步行射门的 GR00T 一次读取跨越约 5.8 秒的 4 张历史图像。如果同一段视频里前后帧被生成成不同的房间或灯光，模型看到的就是一个现实中不会发生的场景。
- **物理不会重新发生。** 生成视频改变的只是画面，球怎样滚、脚怎样接触地面并没有重新计算。把地毯换成更滑的地面，原来的步态和出脚时机就未必成立；涉及摩擦、质量或接触的变化，要回到物理仿真中重新采集。

所以 Cosmos 3 适合承担的角色是**外观多样性的补充**：在几何、动作和物理都不变的前提下，让模型见到更多光照和房间外观。它不能替代新的动作示范，也不能证明动作在新环境中可以执行；可靠性仍要靠闭环仿真和之后的真机测试来检验。

## 规划一组环境评测

随着条件增多，评测的组合数增长得很快。Isaac Lab-Arena 把环境拆成场景（Scene）、机器人与传感器（Embodiment）和任务（Task）三部分，便于组合评测与数据采集；Isaac Lab 组织学习环境，Newton 推进物理，渲染器产生图像。

```{scenario-matrix}
title: 试着规划一组评测
factors:
- [4, 四种地面]
- [3, 三种光照]
- [3, 三种室内布局]
seeds_label: 每种组合的新测试起点数
seeds: 5
scope: 这只是组合计数器，不启动仿真或训练。取消一项表示固定为一种条件。
```

{#experiment}
## 一次扩大一个因素

一个合理的顺序是：绿色球场稳定完成 → 新的起点范围 → 少量光照变化 → 新地面外观 → 新室内布局 → 有测量依据的物理变化。每一步保留前一步作为对照，用同样的完整成功判据比较。如果新变化带来的主要失败是看不清，就补视觉覆盖；如果是走偏或站不稳，就回到纠正示范，或者底层技能与物理参数的校准。

::::{quiz}
同一段动作的视频换了十种背景，就等于获得了十倍不同的动作经验吗？

:::{answer}
不等于。它扩充了视觉条件，但动作和状态的覆盖仍然相同。学会从偏差中恢复、改走别的路线或适应新的地面，需要对应的新轨迹或纠正数据。
:::
::::

::::{quiz}
为什么改变灯光后可以沿用原来的动作标签，而把地面换成更滑的材质就不能？

:::{answer}
灯光只改变画面，球和机器人的运动不变，原来的动作仍然正确；地面更滑会改变步态和接触，原来的动作在新条件下未必能执行，需要重新运行物理仿真并记录新的动作。
:::
::::
