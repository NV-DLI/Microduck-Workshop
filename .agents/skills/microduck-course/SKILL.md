# Student course workflow

Write to the learner: explain why an operation matters, what to do, what to observe, and how to recover from a likely failure. Keep development chronology, old results, demo seeds, recording frame rates and internal acceptance machinery outside student pages; show only the current course version with its current, honest limitations. No em dash (U+2014) in learner-visible text. Lab commands use `scripts/run.py` inside the course container (`scripts/workshop.py` is only a compatibility wrapper); collapse file paths and start-up details of a command into an `{enrichment}` titled 代码关键参数 / Key code parameters. Chinese and English share lesson identifiers, commands, and artifact references.

Use short continuous lessons, a persistent chapter navigation, and local references. Each practical lesson names its prerequisites, parameters, expected outputs, and a question that checks understanding. Copy blocks contain executable commands without terminal prompts; explain parameters beside the command. Never offer a command whose entry point is absent.

Fixed models in `models/` are the downstream default. Training is a separate practice route with a new output directory, seed, budget, and explicit custom-checkpoint opt-in. Never retrain a preserved model to produce course media. Distinguish detection scores, survival rates, local kicks and complete autonomous task success.

Blender component assets retain CAD provenance and licensing. Check assembly and explosion renders from the same camera; validate mesh identities, transforms and browser selection. Do not claim electronic components from one hardware revision represent another revision.

Lesson source is MyST Markdown: `docs/zh/<page>.md` and `docs/en/<page>.md` share file names and section anchors (`{#id}` before each `##` heading). Edit Markdown directly; never regenerate it from `content/course.json`, which is a read-only archive. Interactive figures are directives from `docs/_ext/microduck_course` (`learning-flow`, `concept-diagram`, `course-video`, `course-image`, `scene-cards`, `demonstration`, `robot-anatomy`, `network-diagram`, `platform-diagram`, `training-chart`, `benchmark-chart`, `model-card`, `control-timing`, `code-story`, `scenario-matrix`, `formula`, `quiz`/`answer`, `enrichment`, `lesson-intro`, `recorded-run`); their YAML strings accept inline Markdown. `recorded-run` shows a command the course actually ran (YAML `where`, `recorded`, `command`, optional `image`, `output`, `result`, `caption`): no copy control, real output and interpretation collapsed; use it for commands learners read rather than run. Terminal blocks are ```` ```{code-block} bash ```` with `:class: terminal` (copy button) and a caption saying where they run (`Terminal · 容器内` / `Terminal · inside the container`, or host); every source excerpt is a `{code-story}` (YAML `label`, `source` full-file link, `language`, verbatim `code`, `steps` with zero-based half-open `lines` covering every line once, `title`, `body`): each numbered step and its highlighted chunk are adjacent cells of one grid row (explanation left, code right on desktop; step then code on narrow screens), so a pair always shares its top and bottom; every chunk is rendered once; explanatory folder trees use `:class: workspace-tree`, not a code story. The page shell is the native nvidia-sphinx-theme: grouped left navigation (six numbered parts, seventeen pages; page titles carry their section number, e.g. "3.1 …"), the right "on this page" contents, uncapped page width and horizontal paddings at half the theme default. `docs/_static/microduck.css` holds only those shell adjustments, left-aligned captions and figure styles. Flow figures place four modules per row at 100% desktop zoom (longer flows continue on the next row). Three-module flows spread across the same width: first and last cards align with the same outer padding, and the middle card is centered, with longer connectors and unchanged card/font sizes; flow and concept figures show the diagram first and explanations/controls below without generic "click a module" prompts; connectors need straight end segments clear of card corners. Flow explanation panels initially occupy no space and have no placeholder prompt; hover or focus opens an explanation, clicking pins it, and Close or Escape collapses it. Preserve the readable no-JavaScript fallback. Removed lessons (06-autonomy, 08-aspire, how-to-learn) stay out of the source; their URLs only redirect (06-autonomy to the Part 4 page 06-onboard, how-to-learn to setup). Part 4 (06-perception, 06-onboard) describes the onboard policy's actual sensor pipeline; the `concept-diagram` kind `onboard-sensors` draws one recorded capture (detector boxes in original pixels and the 8×8 ToF ranges, `tof.used: false` and `rgb.detections: false` for the GR00T input) and must keep those values from a completed run; an observation-only ToF lane has no connection to the model. Part 4 stays concise: actual sensor recording, three core steps, the stage flow and the bridge to Part 5, without old private-candidate timelines or success statistics. Code snippets soft-wrap and grow to full height without internal scrollbars or clipped content; copied text stays unchanged. On narrow screens, timing labels sit above full-width timing tracks so cells and labels remain readable. Use event arrays and per-call durations from completed simulation logs, verify recorded source bindings, and keep the public timing-data JSON consistent with both language YAML blocks. Math: write variables in prose as inline math (`$...$`), never as Unicode look-alikes (ωz, rₜ). Each page that uses math has one `{symbols}` block after the lesson intro (YAML `key: {tex, text}`, explanations written for students and specific to that page's context; reuse of a letter with a different meaning gets a different key, e.g. `T_horizon` vs `T_rollout`). Mark every symbol occurrence in `{formula}` blocks, inline math and widget `$...$` strings with `\sym{key}`, or `\symx{key}{TeX}` when the occurrence is written differently (e.g. `q_1` for `q_i`). Unknown or unused keys fail the build. Display formulas get a collapsed "变量含义 / Variable meanings" list automatically; the browser shows explanations on hover, keyboard focus (arrow keys) and tap, with no underline or help cursor. SVG labels inside diagrams stay plain text.

Build with `python3 scripts/build_site.py` (Sphinx, warnings are errors; `--out DIR` for a staging build). Run `python3 scripts/check_course.py` for Markdown source, links and anchors, command references, bilingual topology and fixed-model identities; `--site-only` skips the model and runtime-bundle groups. Inspect desktop pages only (100% zoom at widths such as 1366, 1440 and 1920; the user asked for no phone or mobile testing), copy controls, quiz feedback, local search, language links, media loading, and the actual 3D viewer in a browser before publication. Check the deployed revision after publishing; a local build is not evidence of remote publication.

## Chinese teaching refinement

Prioritize the Chinese edition until the user approves additional languages. Follow the invoked DLI localization methodology: protect code, URLs and mathematical notation; review every learner-visible Chinese segment contextually; use an independent reviewer and retain coverage records outside the student site.

For each theory/practice unit connect the task, motivation, method, equations, actual core implementation, data generation, measured timing and verification. Distinguish pseudocode from executable snippets. Read actual pinned configuration and measured outputs instead of inventing results. Use local KaTeX and accessible responsive vector diagrams; make interactive illustrations state what they do and do not represent.

Do not include completion markers or learner progress. Use a language menu on the normal site and bilingual LMS edition; the English-only LMS edition has no language switch. Use native seekable video controls for long clips and a static expandable contact sheet for detection examples. Anatomy uses the current transparent NPR explorer with direct labels, assembly/explosion/joint modes and a reset; show no stale poster while loading. Preserve the authored Chinese component metadata when rebuilding geometry.

High-resolution studio or trajectory re-renders retain source pose/data provenance in validation records. Student captions describe the observation and its limits without narrating Blender or authoring steps. Never present an offline render as a fresh simulation or as proof of success. Keep original recordings and all model identities unchanged.

## Explained mathematical symbols

Define contextual keys in a page-level `{symbols}` YAML block (`key: {tex: ..., text: ...}`), then use `\sym{key}` or `\symx{key}{custom TeX}` in `{formula}` and inline math. The same letter with different meanings needs different keys. Unknown/unused keys fail the Sphinx build. Explanations can use `$TeX$` segments. Preserve MathML, hover/focus/tap definitions, Escape dismissal, keyboard navigation within each formula, viewport placement and the collapsible symbol list. Verify nested variables, both themes and touch; preserve equation semantics and numerical data. Match filled swatches to bars and line styles to line series, without background badges behind bar values.
